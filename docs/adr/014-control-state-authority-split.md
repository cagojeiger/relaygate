# ADR 014: 제어 상태를 영속 `C`와 리더 로컬 `V`로 나눈다

## 배경

Controller는 두 종류의 질문에 답해야 한다.

1. "이 route가 선언되어 있는가" — 재시작과 리더 교체를 넘어 살아남아야 하는 durable한 사실이다.
2. "이 Gateway가 지금 이 순간 연결되어 있는가" — 연결이 끊기는 순간 거짓이 되는 휘발성 관찰이다.

두 질문을 한 저장소에 넣으면 둘 중 하나가 망가진다. 생존 여부를 영속 FSM에 넣으면 keepalive마다 합의가 필요하고, route를 리더 메모리에만 두면 리더가 바뀔 때 directory가 사라진다.

[ADR 002](002-current-state-cluster-and-recovery.md)는 "현재 권한 주체, 재검증된 제어 세션, 광고된 소유자 Relay 주소는 리더 로컬 휘발 상태다"라고 기록했지만 왜 그렇게 나누는지는 남기지 않았다. 이 결정이 그 근거를 기록한다.

## 결정

제어 상태를 두 계층으로 분리하고 각각의 저장 위치를 고정한다.

| 계층 | 저장 위치 | 내용 | 수명 |
| --- | --- | --- | --- |
| `C` | Raft FSM, 영속 log/snapshot | `ClusterEpoch`, capacity 상한, 현재 `GatewaySession`, exact route | 재시작·리더 교체를 넘어 유지 |
| `V` | 현재 리더 프로세스 메모리 | `AuthorityId`, 제어 세션, owner relay address, 재검증 상태, grace deadline | 리더 임기 동안만 |

- `C`에는 시각, 제어 세션 ID, relay address, tombstone, route 이력을 저장하지 않는다.
- `V`는 어떤 경우에도 Raft에 기록하지 않는다. 리더십 상실은 `V`를 전부 버리며 `C`는 건드리지 않는다.
- Route는 exact `C`와 exact `V`가 모두 존재할 때만 사용할 수 있다. 둘 중 하나만으로는 Open을 허용하지 않는다.
- Gateway는 제어 세션을 새로 열 때마다 현재 바인딩 전체 snapshot으로 `V`를 재구축한다. `C`는 이때 재사용된다.

### 왜 생존 여부를 `C`에 넣지 않는가

생존 신호를 영속 FSM에 넣으면 Gateway 수에 비례하는 합의 트래픽이 발생한다. Gateway 1,000대가 5초마다 갱신하면 초당 200개 명령이 Raft log에 기록되고 과반 fsync를 거친다. 상태가 거의 바뀌지 않는 directory를 위해 지속적인 디스크 쓰기를 감수하는 셈이다.

전체 상태를 주기적으로 재전송하는 방식은 더 나쁘다. Gateway당 binding 512개를 5초 주기로 보내면 1,000대 기준 초당 26MB가 Raft를 통과한다.

반면 제어 스트림이 살아 있다는 사실 자체는 이미 무료로 관찰할 수 있다. `V`를 리더 메모리에 두면 합의 비용이 0이다. 리더가 바뀌면 모든 Gateway가 어차피 재연결해야 하므로, `V`를 잃는 것은 손실이 아니라 정상 절차다.

### 증분 명령을 유지하는 이유

신뢰할 수 있는 제어 스트림 위에서는 주기적 전체 재전송이 낭비다. Bind와 Unbind는 발생 시점에 `DeclareRoute`/`WithdrawRoute`로 즉시 반영하고, 전체 snapshot은 세션을 새로 열 때만 보낸다. 스트림 종료가 곧 철회 신호이므로 정상 경로에는 타이머가 필요 없다.

## 결과

- Route directory는 리더 교체를 넘어 살아남고, 생존 관찰은 합의 비용 없이 유지된다.
- Open 허용 판정은 `C` 조회와 `V` 조회를 모두 거쳐야 한다. 두 계층을 교차 확인하는 비용은 판정 경로에 남는다.
- 리더 교체 직후에는 아직 재연결하지 않은 Gateway의 route가 `C`에 있으나 사용 불가 상태다. 이 구간의 처리는 [ADR 015](015-leader-driven-expiry.md)가 정의한다.
- `V`가 리더 임기에 묶이므로 `AuthorityId`는 term마다 새로 발급된다. 이전 권한 주체가 발급한 context는 자동으로 stale이 된다.
- 관찰 인터페이스는 `C` 개수와 `V` 개수를 분리해 보고한다. 둘을 합산한 단일 수치는 의미가 없다.
